## Завдання 1. Аналіз відкритих портів (2 бали)

**Команда:**

```bash
ss -tuln
```

**Результати аналізу:**

| Протокол | Порт | Стан | Призначення |
|---|---|---|---|
| TCP | 22 | LISTEN | SSH |
| TCP | 53 | LISTEN | DNS |
| UDP | 323 | UNCONN | Служба синхронізації часу |

**Пояснення:**

Команда `ss -tuln` дозволяє переглянути мережеві сокети, які очікують на підключення або приймання даних.

TCP-порт 22 зазвичай використовується для SSH, а порт 53 — для DNS. UDP-порт 323 може використовуватися службою синхронізації часу.

Стан `LISTEN` означає, що TCP-сокет очікує на вхідні з'єднання. Стан `UNCONN` для UDP є нормальним, оскільки цей протокол працює без встановлення з'єднання.

Таким чином, було визначено щонайменше три мережеві порти та їхні стани.

## Завдання 2. Аналіз процесів, що слухають порти (2 бали)

**Команда:**

```bash
sudo ss -tulpn
```

**Результати аналізу:**

| Процес | PID | Порт | Протокол |
|---|---|---|---|
| systemd-resolved | 200 | 53 | TCP/UDP |
| systemd-timesyncd | 201 | 35002 | UDP |
| python3 | 464 | 8080 | TCP |

**Пояснення:**

Команда `ss -tulpn` дозволяє визначити процеси, які використовують мережеві порти.

Для відображення інформації про системні процеси команда виконувалася з правами адміністратора через `sudo`.

- `systemd-resolved` — системна служба обробки DNS-запитів.
- `systemd-timesyncd` — служба синхронізації системного часу.
- `python3` — процес локального HTTP-сервера, запущеного для дослідження мережевих портів.

Для запуску додаткового локального сервера було використано команду:

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

Після запуску сервер почав прослуховувати TCP-порт 8080. Повторна перевірка командою `sudo ss -tulpn` дозволила визначити його PID — 464.

PID — це числовий ідентифікатор процесу в операційній системі. Він може змінюватися після перезапуску програми.

## Завдання 3. Перевірка TCP-з'єднання (2 бали)

**Команда:**

```bash
nc -vz -w 5 google.com 80
```

**Результат:**

```text
Connection to google.com (172.217.20.78) 80 port [tcp/http] succeeded!
```

**Аналіз результату:**

- Тип з'єднання: TCP.
- Домен: google.com.
- IP-адреса сервера: 172.217.20.78.
- Порт: 80.
- Призначення порту: HTTP.
- Результат: TCP-з'єднання успішно встановлено.

**Пояснення:**

Команда `nc` перевіряє можливість встановлення мережевого з'єднання.

Параметр `-v` виводить детальну інформацію, `-z` виконує перевірку порту без передавання звичайних даних, а `-w 5` обмежує час очікування п'ятьма секундами.

Повідомлення `succeeded!` підтверджує, що вдалося встановити TCP-з'єднання з сервером Google через порт 80.

## Завдання 4. Порівняння TCP та UDP (3 бали)

### Перевірка UDP

**Команда:**

```bash
nc -u -vz -w 5 8.8.8.8 53
```

**Результат:**

```text
Connection to 8.8.8.8 53 port [udp/domain] succeeded!
```

### Перевірка TCP

**Команда:**

```bash
nc -vz -w 5 8.8.8.8 53
```

**Результат:**

```text
Connection to 8.8.8.8 53 port [tcp/domain] succeeded!
```

### Порівняння результатів

| Характеристика | TCP | UDP |
|---|---|---|
| IP-адреса | 8.8.8.8 | 8.8.8.8 |
| Порт | 53 | 53 |
| Встановлення з'єднання | Так | Ні |
| Підтвердження встановлення з'єднання | Є | Немає |
| Гарантія доставки на рівні протоколу | Передбачені механізми надійної доставки | Не передбачена |
| Результат команди | succeeded! | succeeded! |

**Пояснення:**

TCP є протоколом зі встановленням з'єднання. Перед передаванням даних виконується узгодження з'єднання між пристроями. TCP також має механізми підтвердження отримання та повторної передачі втрачених даних.

UDP працює без попереднього встановлення з'єднання. Він не гарантує доставку пакетів і не забезпечує підтвердження їх отримання на рівні самого протоколу.

Під час перевірки обидві команди `nc` повідомили `succeeded!`. Однак для UDP це повідомлення не є доказом того, що віддалений DNS-сервер отримав пакет і надіслав відповідь.

**Висновок:** TCP забезпечує встановлення з'єднання та механізми надійної передачі даних, тоді як UDP не потребує встановлення з'єднання й має менші накладні витрати. Результати тестування показують важливу різницю між перевіркою TCP-з'єднання та перевіркою UDP-порту.

## Завдання 5. DNS-резолвінг (3 бали)

**Команда:**

```bash
nslookup github.com
```

**Результат:**

```text
Server:         10.255.255.254
Address:        10.255.255.254#53

Non-authoritative answer:
Name:   github.com
Address: 140.82.121.3
```

**Аналіз результату:**

- Доменне ім'я: github.com.
- IP-адреса домену: 140.82.121.3.
- DNS-сервер, який обробив запит: 10.255.255.254.
- Порт DNS-сервера: 53.
- Тип відповіді: Non-authoritative answer.

**Пояснення:**

DNS використовується для перетворення доменних імен на IP-адреси.

Команда `nslookup github.com` надіслала DNS-запит і отримала IP-адресу 140.82.121.3.

Адреса 10.255.255.254 — це DNS-сервер, до якого звернулася система Ubuntu в середовищі WSL 2.

Повідомлення `Non-authoritative answer` означає, що відповідь була отримана не безпосередньо від авторитетного DNS-сервера домену, а через інший DNS-сервер.

**Висновок:** DNS-резолвінг працює успішно, оскільки доменне ім'я github.com було перетворено на IP-адресу.
